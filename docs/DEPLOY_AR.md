# دليل إطلاق شهم خطوة بخطوة

هذا الدليل يوصلك من الملفات إلى منصة شغالة على رابطك الخاص، يستخدمها العملاء ويدفعون اشتراكهم.
رتّبته حسب الأولوية: أول ثلاث مراحل تكفي لتشغيل المنصة وتجربتها مع عملاء حقيقيين، والباقي يفعّل التنفيذ على المنصات الخارجية.

> قبل البدء: كل المفاتيح والتوكنات تُوضع في إعدادات الاستضافة فقط، ولا تُرفع على GitHub أبدًا.

---

## المرحلة 1 — التشغيل (ساعة تقريبًا)

### 1. ارفعي الكود على GitHub
1. أنشئي مستودعًا **خاصًا (Private)** جديدًا على GitHub باسم `sahm`.
2. فكّي ضغط الملف وارفعي محتواه كما هو (المجلدات `app` و`web` و`tests` و`docs` والملفات `Dockerfile` و`requirements.txt` و`.env.example`).
3. تأكدي أن ملف `.env` الحقيقي **غير موجود** في المستودع (الملف `.gitignore` يمنعه).

### 2. أنشئي المفاتيح السرية
على جهازك (يحتاج Python):
```bash
python -c "import secrets;print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"
```
الأول هو `SAHM_SECRET_KEY` والثاني `SAHM_ENCRYPTION_KEY`. احفظيهما في مكان آمن.

**مهم:** إذا ضاع مفتاح التشفير، تتعطل كل الحسابات المربوطة ويحتاج العملاء ربطها من جديد.

### 3. انشري على Railway (أو أي استضافة تدعم Docker وقرصًا دائمًا)
1. سجّلي في railway.com، ثم **New Project ← Deploy from GitHub repo**، واختاري `sahm`. سيتعرف على `Dockerfile` تلقائيًا.
2. من الخدمة: **Settings ← Volumes ← Add Volume** واجعلي مسار التركيب `/data`.
   هنا تُحفظ قاعدة البيانات والصور. بدونه تضيع البيانات عند كل نشر.
3. من **Settings ← Networking** اضغطي **Generate Domain**، فيعطيك رابطًا مثل `sahm-production.up.railway.app`.
4. من **Variables** أضيفي:
   - `SAHM_ENV=production`
   - `SAHM_BASE_URL=https://<الرابط من الخطوة السابقة>`
   - `SAHM_SECRET_KEY` و`SAHM_ENCRYPTION_KEY` من الخطوة 2.
   - `SAHM_ADMIN_EMAILS=<إيميلك>`
5. انتظري اكتمال النشر وافتحي `https://<رابطك>/healthz`. يجب أن تري `"status":"ok"`.

البديل: Render (Web Service من Docker مع Persistent Disk على `/data`)، أو أي خادم VPS مع `docker compose up -d`.

### 4. فعّلي عقل الفريق (مفتاح Anthropic)
1. من console.anthropic.com أنشئي مفتاح API وأضيفي رصيدًا.
2. أضيفي في Variables: `ANTHROPIC_API_KEY=...`
3. اختياري: `ANTHROPIC_MODEL` و`ANTHROPIC_FAST_MODEL`، والقيم الافتراضية مضبوطة.

الآن المحادثات مع الأربعة تعمل فعليًا، وكذلك:
- خطط نجد ووضع الفريق.
- مواقع ساري ونشرها.
- تصاميم سلاف.
- أتمتة سند المجدولة والـWebhook والإشعارات.

### 5. البريد (للتذكيرات والتقارير وخطوات الإيميل في الأتمتة)
استخدمي مزود SMTP مثل Resend أو Zoho Mail أو Amazon SES، ووثّقي نطاقك عنده (سجلات SPF وDKIM) حتى لا تذهب الرسائل للسبام. ثم أضيفي:
```
SMTP_HOST=   SMTP_PORT=587   SMTP_USER=   SMTP_PASSWORD=
SMTP_FROM=SAHM | شهم <no-reply@نطاقك>
```

## المرحلة 2 — الدومين والهوية

1. اشتري دومينًا (مثل `sahm.sa` من SaudiNIC أو `.com` من أي مسجّل).
2. في Railway: **Settings ← Networking ← Custom Domain** وأضيفي مثلًا `app.نطاقك`، ثم ضعي سجل CNAME الذي يعطيك إياه عند مسجّل الدومين.
3. حدّثي `SAHM_BASE_URL=https://app.نطاقك`.
4. **مُستحسن أمنيًا:** أضيفي دومينًا فرعيًا ثانيًا لمواقع العملاء مثل `sites.نطاقك` على نفس الخدمة، وضعي `SAHM_SITES_BASE_URL=https://sites.نطاقك`. هكذا لا تشارك صفحات العملاء نطاق المنصة أبدًا.
5. صفحة الهبوط على `/`، والمنصة على `/app`، والخصوصية على `/privacy`، والشروط على `/terms`.
   راجعي نصي الخصوصية والشروط مع مختص قانوني قبل الإطلاق العام.

## المرحلة 3 — الدفع (ميسر)

1. سجّلي في moyasar.com. **تأكدي أولًا من ميسر أنهم يقبلون وثيقة العمل الحر لتفعيل الحساب الحي.** إن لم يقبلوها فستحتاجين سجلًا تجاريًا.
2. ابدئي بمفاتيح **الاختبار** (`sk_test_...`):
   - `MOYASAR_SECRET_KEY=sk_test_...`
3. من لوحة ميسر أنشئي **Webhook**:
   - الرابط: `https://app.نطاقك/api/billing/webhook`
   - الحدث: `payment_paid`
   - Shared secret: قيمة عشوائية، وضعي نفسها في `MOYASAR_WEBHOOK_SECRET`.
4. جرّبي الاشتراك من صفحة الاشتراك ببطاقة اختبار من وثائق ميسر، وتأكدي أن الباقة تتفعل تلقائيًا.
5. عند الجاهزية استبدلي بالمفتاح الحي `sk_live_...`.

الأسعار والحدود في ملف `app/billing.py` (المتغير `PLANS`)، وهي اقتراح أولي تقدرين تعدّلينه.

## المرحلة 4 — حسابات سلاف: إنستقرام وفيسبوك (Meta)

1. في developers.facebook.com: **Create App ← Business**.
2. أضيفي المنتجات: **Facebook Login for Business** و**Instagram** (Instagram API with Facebook Login).
3. في إعدادات Facebook Login، الحقل Valid OAuth Redirect URIs:
   `https://app.نطاقك/api/channels/meta/callback`
4. في **App Settings ← Basic**:
   - Privacy Policy URL: `https://app.نطاقك/privacy`
   - User data deletion: نفس الرابط (فيه تعليمات الحذف).
   - انسخي App ID وApp Secret إلى `META_APP_ID` و`META_APP_SECRET`.
5. **تجربة فورية:** وهو في وضع التطوير، يقدر كل شخص له دور في التطبيق (أضيفيهم من App Roles) أن يربط صفحاته وحساب إنستقرام الاحترافي المرتبط بها، ويجرّب النشر فعليًا.
6. **للعملاء العامين:** قدّمي **App Review** للصلاحيات التالية مع فيديو يشرح الاستخدام، ووثّقي النشاط (Business Verification):
   `pages_show_list, pages_read_engagement, pages_manage_posts, pages_manage_engagement, read_insights, business_management, instagram_basic, instagram_content_publish, instagram_manage_comments, instagram_manage_insights`

ملاحظات:
- إنستقرام يقبل حسابات **احترافية** (أعمال أو صانع محتوى) مربوطة بصفحة فيسبوك.
- إنستقرام يحتاج صورة أو فيديو في كل منشور.
- لإنستقرام حد يومي لعدد المنشورات عبر الواجهة البرمجية.

## المرحلة 5 — واتساب للأعمال (سلاف + سند)

كل عميل يربط رقمه بنفسه من صفحة «الحسابات المربوطة». يحتاج: Phone Number ID، وWABA ID، وتوكن دائم لمستخدم نظام.

أنتِ (كمنصة) تضبطين الـWebhook مرة واحدة في تطبيق Meta:
1. أضيفي منتج **WhatsApp** للتطبيق.
2. في إعدادات الـWebhook:
   - Callback URL: `https://app.نطاقك/hooks/whatsapp`
   - Verify token: نفس قيمة `WHATSAPP_VERIFY_TOKEN`
3. اشتركي في حقل `messages`.
4. لكي تصل رسائل رقم العميل إلى شهم، يجب أن يكون تطبيقك مشتركًا في حساب واتساب للأعمال (WABA) الخاص به.

قواعد واتساب:
- الرد الحر مسموح خلال 24 ساعة من آخر رسالة للعميل.
- خارج هذه المدة تُستخدم **قوالب معتمدة** فقط، وللمشتركين الموافقين فقط.
- Meta تحاسب على المحادثات حسب تسعيرها.

## المرحلة 6 — تيك توك

1. في developers.tiktok.com أنشئي تطبيقًا وأضيفي **Login Kit** و**Content Posting API** (مع Direct Post).
2. Redirect URI: `https://app.نطاقك/api/channels/tiktok/callback`
3. الصلاحيات: `user.info.basic` و`video.publish`.
4. أضيفي `TIKTOK_CLIENT_KEY` و`TIKTOK_CLIENT_SECRET`.
5. **منشورات الصور:** وثّقي ملكية نطاقك في بوابة تيك توك، لأن تيك توك يسحب الصور من الروابط. الفيديو يُرفع مباشرة ولا يحتاج هذا.
6. **مهم:** قبل اجتياز **Audit** تيك توك، النشر يكون للحسابات الخاصة وبظهور خاص فقط. قدّمي طلب التدقيق عند الجاهزية.

## المرحلة 7 — تيليجرام وn8n
- **تيليجرام:** لا يحتاج إعدادًا منك. العميل ينشئ بوتًا من @BotFather ويربطه، مع قناته اختياريًا (والبوت مشرف فيها).
- **n8n:** العميل يدخل رابط n8n الخاص به ومفتاح API.

## سناب شات
النشر الآلي على سناب متاح لشركاء سناب المعتمدين فقط. لذلك سلاف تجهّز المحتوى والتصاميم، والعميل ينشر بنفسه.
إذا حصلتِ لاحقًا على وصول Public Profile API من سناب، نضيف التكامل.

## التشغيل اليومي

- **العامل الخلفي** (نشر المجدول، والأتمتة، والتذكيرات، وتحديث الأرقام) يعمل داخل نفس الخدمة كل 30 ثانية. لا يحتاج إعدادًا.
- **النسخ الاحتياطي:** قاعدة البيانات ملف واحد `/data/sahm.db`، مع الصور في `/data/media`.
  - فعّلي النسخ الاحتياطي للـVolume في الاستضافة.
  - أو انسخي احتياطيًا يدويًا أسبوعيًا:
    ```bash
    sqlite3 /data/sahm.db ".backup /data/backup-$(date +%F).db"
    ```
- **المراقبة:** الرابط `/healthz` يبين ما هو مفعّل (المزود، البريد، الدفع، Meta، تيك توك).
- **التوسع:** SQLite يخدم آلاف المستخدمين في البداية بكفاءة. عند النمو الكبير ننتقل إلى PostgreSQL، والبيانات معزولة في طبقة واحدة `app/db.py` لتسهيل ذلك.

## قائمة ما قبل الإطلاق
- [ ] `/healthz` يعمل و`model_configured: true`
- [ ] سجّلت حسابًا وجرّبت الأربعة: خطة نجد، موقع ساري (ونشره ونموذجه)، تصميم سلاف، أتمتة سند
- [ ] ربطت قناة تيليجرام ونشرت منشورًا تجريبيًا
- [ ] ربطت صفحتك وإنستقرامك (وضع التطوير) ونشرت تجربة
- [ ] اشتراك تجريبي عبر ميسر فعّل الباقة تلقائيًا
- [ ] وصلك تذكير مهمة على الإيميل
- [ ] راجعت الخصوصية والشروط ووضعت إيميل التواصل في `SAHM_ADMIN_EMAILS`
- [ ] الدومين وشهادة HTTPS يعملان
